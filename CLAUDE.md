# Capacity Model: rules for Claude Code

## Roles
- Siri is the architect. You are the builder.
- `docs/Capacity_Model_Spec.md` is the source of truth for every input, formula, default, and check.
- Do not change an assumption, formula, or default on your own. If something in the spec is unclear, missing, or looks wrong, stop and ask Siri before building it.

## Honesty
- All data is synthetic, generated by this code. Never use, fetch, or invent real company, patient, or employee data.
- Label generated data and outputs as synthetic in file names, headers, and the README.

## How to build
- Every input lives in the YAML files (`assumptions.yaml`, `sites.yaml`, `skills.yaml`, `scenarios/`). No numbers hard-coded in the logic.
- Use a fixed random seed so every run produces the same data.
- Write plain-language comments that explain the WFM idea behind the code, not just what the code does. Siri reads the code so she can explain it in interviews.
- Each validation check in spec Section 9 becomes a pytest test. A session's work isn't done until its tests pass.

## How to work
- Work one task at a time. At the end of each task, stop and summarize: what you created or changed, which tests ran and their results, and any open questions.
- Commit to git after each passing step, with a clear message.
- Environment: Windows, PowerShell, Python in `.venv`. Run Python as `.venv\Scripts\python`.
